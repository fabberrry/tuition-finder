# PRD: Tuition Discovery & Private Tutor Marketplace

## 1. Product Title

**Product Name:** TuitionLens  
**Product Type:** Hyperlocal EdTech Marketplace  
**Primary Platform:** Responsive Website  
**Future Platforms:** Android App, iOS App  
**Primary Users:** Students, parents, tuition centers, private tutors  
**Market Type:** Two-sided marketplace with trust, discovery, booking, and lead-generation layers

---

## 2. Executive Summary

TuitionLens is a hyperlocal EdTech marketplace that helps students and parents discover, compare, evaluate, and book nearby tuition centers and private tutors.

Today, students waste time physically visiting multiple tuition centers just to check demo class quality, teacher quality, batch timings, seat availability, fees, environment, reviews, and distance feasibility. Tuition owners and private tutors also struggle to build digital visibility, generate qualified leads, and communicate real-time batch availability.

TuitionLens solves this by creating a trusted platform where students can search by class, board, subject, exam, fees, distance, ratings, timing, vacancy, and teaching mode. They can view teacher profiles, demo videos, verified reviews, batch-level vacancy, tuition photos, fee structures, and private tutor options before booking a demo or contacting the provider.

The product should not be built as a generic listing website. The winning strategy is to build a **trusted tuition decision platform** with teacher-level proof, verified reviews, batch-level vacancy, and hyperlocal search.

---

## 3. Problem Statement

Students and parents lack a reliable, transparent, and real-time way to evaluate tuition centers and private tutors nearby.

The current process is offline-heavy and inefficient. Students often visit multiple tuition centers physically before discovering that:

- The required subject is not available.
- The preferred batch is full.
- The teacher quality is poor.
- The demo class does not match expectations.
- The tuition center is too far.
- The fees are outside budget.
- The environment is not suitable.
- The teacher does not actually specialize in the weak subject.
- Reviews are unavailable or unreliable.

This creates high search effort, wasted time, poor decision-making, and low trust.

**Refined problem statement:**

> Students need a trusted hyperlocal platform to compare tuition centers and private tutors using verified teacher quality, demo videos, batch availability, fees, reviews, distance, and timing before physically visiting or enrolling.

---

## 4. Why This Problem Matters

Tuition selection is a high-impact academic and financial decision.

A wrong tuition choice can lead to:

| Area | Impact |
|---|---|
| Academic performance | Student may not improve in weak subjects |
| Time | Student and parent waste time visiting centers |
| Money | Fees may be paid to unsuitable institutes |
| Travel | Daily commute may become unsustainable |
| Trust | Parents depend on word-of-mouth instead of verified data |
| Business | Good local teachers remain undiscovered |
| Marketplace inefficiency | Demand and supply fail to match properly |

For students in Classes 8–12, JEE, NEET, CUET, and board exam preparation, tuition is not a casual service. It directly affects academic outcomes, family spending, and student confidence.

## 7. Jobs To Be Done

### Student Jobs

1. When I am weak in a subject, I want to find a good teacher nearby so that I can improve quickly.
2. When I search for tuition, I want to compare fees, distance, vacancy, and reviews so that I can avoid unnecessary visits.
3. When I see a tuition center, I want to watch a demo video so that I can judge teaching quality before going there.
4. When I am unsure between centers, I want to compare them side-by-side so that I can make a confident decision.

2. When comparing options, I want to check environment, safety, reviews, and fees so that I can choose responsibly.
3. When booking a demo, I want confirmation and reminders so that the process is smooth.

1. When I have vacant seats, I want to show availability so that students can join the right batch.
2. When students search nearby, I want my center to appear with complete details so that I can get leads.

## 24. Ranking and Recommendation Logic

### MVP Ranking Formula

```text
Ranking Score =
Distance Score x 20%
+ Subject Match x 20%
+ Vacancy Availability x 15%
+ Teacher Rating x 15%
+ Review Trust Score x 10%
+ Fee Fit x 10%
+ Demo Availability x 5%
+ Listing Freshness x 5%
```

### Ranking Factors

| Factor | Logic |
|---|---|
| Distance | Closer centers get higher score |
| Subject match | Exact subject match gets highest score |
| Vacancy | Available batches rank higher |
| Teacher rating | Teacher-level quality matters |
| Review trust | Verified reviews weighted higher |
| Fee fit | Within student budget ranks higher |
| Demo availability | Listings with demo videos rank higher |
| Freshness | Recently updated listings rank higher |

### Recommendation Explanation

The product should explain why a listing is recommended.

Example:

```text
92% Match
- 1.2 km away
- Class 10 Maths available
- Evening batch has 3 seats
- Fee fits your budget
- Teacher has 4.7 rating
```

## 25. Vacancy Management Logic

### Batch Capacity Model

Each batch should store:

- Total capacity
- Filled seats
- Vacant seats
- Last updated timestamp
- Update source

Formula:

```text
vacant_seats = capacity - filled_seats
```

### Vacancy Status

| Status | Condition |
|---|---|
| Available | vacant_seats > 5 |
| Few seats left | vacant_seats between 1 and 5 |
| Full | vacant_seats = 0 |
| Not recently updated | last_updated > 7 days |
| Unverified | owner entered but not validated |

### Vacancy Trust Rules

1. Show “Updated X days ago”.
2. Lower ranking if vacancy is stale.
3. Allow students to report mismatch.
4. Penalize repeated false vacancy reports.
5. Admin can audit suspicious centers.

## 39. Data Integrity Rules

1. A batch cannot have `filled_seats > capacity`.
2. A review must be linked to a real student account.
3. Verified reviews require demo booking or enrollment proof.
4. A teacher cannot be assigned to a center without center approval.
5. Vacancy update must maintain audit logs.
6. Duplicate centers with same phone/address should be flagged.
7. Demo video must be approved before public display.
8. Friend visibility must be opt-in.
9. Owner cannot delete negative verified reviews.
10. Admin actions must be logged.

### Vacancy Constraint Example

```sql
ALTER TABLE batches
ADD CONSTRAINT check_filled_not_exceed_capacity
CHECK (filled_seats <= capacity);
```

## 49. Final PM Recommendation

TuitionLens should not be built as a simple directory or listing website. That would be too easy to copy and would not create enough trust or defensibility.

The product should be built as a **trusted tuition decision marketplace**.

The strongest wedge is:

> **Teacher-level demo proof + verified reviews + real-time batch vacancy + hyperlocal learning-fit search.**

### Recommended MVP Positioning

```text
Find the right tuition near you before visiting.
Compare teachers, demos, fees, reviews, batch timings, and seat availability in one place.
```

### Recommended MVP Strategy

1. Launch in one dense locality.
2. Focus on Class 9–12 CBSE and core subjects first.
3. Manually onboard high-quality tuition centers.
4. Make data completeness and verification the core advantage.
5. Use demo booking as the primary conversion event.
6. Monetize only after owners see lead value.
7. Delay social features until privacy and trust are mature.
8. Build review verification and vacancy freshness from day one.

### Final Verdict

A FAANG-level product review would likely approve this direction if the team stays focused on marketplace liquidity, trust, and narrow initial scope.

The product will fail if it tries to become everything at once.

The product can win if it becomes the most trusted and useful local decision layer for tuition selection.
